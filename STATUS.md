# STATUS — QuranRu

## Текущее состояние

Русскоязычное приложение для чтения Корана: арабский текст, перевод Кулиева, аудио с
пословной подсветкой, азкары. Веб + нативные обёртки iOS и Android через Capacitor.

Снято с **QuranIng** (`~/Desktop/QuranIng`, ветка `design/v2`, коммит `7b1c6ad`)
2026-08-09 и упрощено: без ингушского языка, четыре темы вместо двенадцати, два чтеца
вместо восьми, плюс задел под разделы «Намаз» и «Кибла».

Первичное упрощение завершено. Приложение собирается и **проверено на
iOS-симуляторе вживую**: чтение, воспроизведение с караоке-подсветкой,
скачивание сур на устройство и игра с диска — работают.

## Известные ограничения

- **Офлайн-аудио только в нативной обёртке.** В браузере `<audio>` не читает Cache API
  без service worker'а; UI показывает это явно, а не молчит.
- **Оценка размера загрузки — расчётная.** 139 КБ на аят выведено из реальной
  длительности чтения Аляфаси (29.5 ч, замерено по 114 файлам quranicaudio) при
  64 kbps → ~850 МБ на весь Коран. В коде стоит `CHECK:` — уточнить по факту.
- **Живая проверка шла в iOS-симуляторе,** не в браузере. Прогон нашёл три вещи,
  которые сборка не ловит: горизонтальную прокрутку всей страницы, «Мусхаф» в роли
  тёмной темы и полностью нерабочее скачивание (CORS). Один раз WebView ушёл в
  чёрный экран — воспроизвести не удалось; вероятная причина (фризы от тяжёлых
  вычислений в рендере) устранена, а на будущее добавлен глобальный перехват
  ошибок, чтобы вместо пустого экрана было видно сообщение.
- **Android собран и прогнан вживую** (эмулятор Medium_Phone, Android 37 preview).
  Работают: чтение, докачка аудио через CapacitorHttp, воспроизведение,
  фоновое воспроизведение (очередь ушла с 1:1 на 1:6 при свёрнутом приложении),
  аппаратная «назад». Сборка требует JDK 21 — на JDK 25 Gradle 8.14 падает
  с «Unsupported class file major version 69».
  Не проверено: реальный звук в динамике (у эмулятора нет вывода — судим по
  тому, что очередь аятов продолжала идти) и поведение на физическом устройстве.

## Веб-версия для теста

Выложена на **https://l.asrbook.ru** (VPS 85.198.86.41, Caddy, `root * /var/www/quran-ru`).
Раскладывается одной командой из корня проекта:

```
npm run build && rsync -az --delete dist/ root@85.198.86.41:/var/www/quran-ru/
```

Прежний адрес этого поддомена (`/opt/quraning/web`) не удалён — откат делается
возвратом одной строки `root` в `/etc/caddy/Caddyfile` (резервные копии там же).

В браузере не работает только скачивание аудио в память устройства — оно на
нативных плагинах. Стрим, чтение, поиск, азкары, темы работают.

| 2026-08-10 | Метод расчёта вынесен в интерфейс, а не зашит | Между 16° и 18° для фаджра в Назрани около 17 минут. | 2026-08-10 | Цветной таджвид скрыт, а не удалён | Решение владельца — вернуться к нему позже. | 2026-08-10 | Тон «Мусхафа» запечён в саму текстуру, а не наложен в CSS | Фотография бумаги почти белая: бежевый нужно УМНОЖИТЬ на неё, иначе зерно гаснет (перепад ±8 уровней превращается в ±2). Умножать в браузере — это `mix-blend-mode`, который в «Авроре» уже стоил плавности прокрутки. Цена: сменить оттенок = пересобрать webp из paper-texture.jpg, и `--canvas` обязан совпадать с тоном файла |
| 2026-08-10 | Аппаратная «назад» на Android — свой обработчик через `@capacitor/app` | Без плагина событие до JS не доходило, и Capacitor просто закрывал активити: первое же «назад» с любого внутреннего экрана выбрасывало на рабочий стол. Признак корня — поле `root` в первой записи истории; в корне сворачиваем, а не закрываем, чтобы «назад» во время чтения не обрывало аудио |
| 2026-08-10 | Анимация Авроры — только `opacity` и `transform` на маленьких слоях | Это единственные свойства, которые уходят в композитор: слой растеризуется раз и дальше живёт на GPU. Анимировать `background-position` или градиентные стопы означало бы перерисовку полноэкранного слоя каждый кадр — фон работает часами, цена ошибки высокая. По той же причине нет `filter: blur()`, хотя он есть во всех рецептах «aurora background»: радиальные градиенты и так мягкие, а blur роняет кадры на слабых телефонах |
| 2026-08-10 | Волна — шесть дуг с общим кадром и разными `animation-delay`, а не вращающийся слой | Вращение по кругу на экране 9:19,5 даёт эллипс, который нужно подгонять под пропорции вьюпорта. Фазовый сдвиг по шести точкам периметра даёт то же ощущение обхода, работает на любом экране и стоит шесть маленьких текстур вместо одной огромной |
| 2026-08-10 | Главный экран — плоский список сур, без деления на джузы | Заголовки «Джуз N» внутри списка давали «1 → 3 → 4 → 6» (джузы 2 и 5 начинаются посреди Бакары и Ан-Нисы). Сделанный взамен переключатель «Суры / Джузы» снят по решению владельца: экран открывают, чтобы найти суру. Код разреза — в истории git, коммит `98e3095` |
| 2026-08-10 | На узком экране настройки — нижний шит, а не карточка у кнопки | На телефоне «карточка» занимала почти весь экран, а WKWebView гасит edge-swipe, так что системный «назад» её не закрывал. У шита есть хваталка и привычный смах вниз |
| 2026-08-11 | Дефолт времени намаза — «Назрань 2», ихтият измерен, а не придуман | Это расписание, по которому живут мечети Ингушетии. Углов у него нет: и 1Muslim («Назрань 2»), и Sajda («Назрань», у них помечено как сверенное) держат его готовой таблицей, а первоисточник не публикует никто. Копировать чужую таблицу нельзя, поэтому расписание воспроизводится расчётом: углы ДУМ России 16°/15° плюс поправки, снятые с самих расписаний (зухр +6, магриб +1, аср +1, иша +2, фаджр −1). Раньше ихтията здесь не было принципиально — придумывать поправку к времени поклонения нельзя; теперь он измерен. Обе таблицы совпали по всем шести временам на 11.08.2026, сверка по 123 дням 2026 года даёт среднюю ошибку меньше минуты и худшую две. Точнее формулой не выйдет: у расписания своя астрономическая реализация. Промахи почти всегда в сторону «позже» — опоздать на минуту безопасно, начать раньше времени нет. Неподтверждённый метод «Муфтият Ингушетии» (16°/16° с одного сайта) убран: рядом со сверенным он только сбивал бы с толку |
| 2026-08-10 | Перетаскивание шита — нативный `touchmove` с `passive:false` | React подписывается пассивно, WebKit забирает вертикальный жест себе как оверскролл и шлёт touchcancel — смах не срабатывал вовсе. Заодно понадобилось глушить синтетический клик после жеста, иначе смах переключал тему под пальцем |
| 2026-08-09 | Ассеты `public/` коммитятся в git | Как в оригинале. В день переноса это спасло проект: 1900 удалённых локально файлов восстановились из git |
