## Общий код и независимые выпуски платформ

`l.asrbook.ru`, iOS и Android используют общий код `src/`/`public/`, но
выпускаются независимо по явной задаче владельца. Web-деплой не меняет уже
опубликованную iOS-сборку; нативные assets обновляются только через
`npm run sync`. В отчёте обязательно указывать, какие контуры действительно
обновлены, а неподтверждённые платформы автоматически не публиковать.

### 2026-08-30 — производительность iOS и единый визуальный язык, версия 1.2 (4)

Работа по жалобе владельца: «программа дёрганная, немного лагает, особенно при
свайпе назад, входе в приложение и прокрутке».

**Измеримое.** Стартовый JS-чанк — **4 576 395 → 323 860 байт** (gzip 100,8 КБ).
Текст Корана с переводом (3,58 МБ) и десять из одиннадцати экранов вынесены в
отдельные чанки; словарь переводов прогревается в простое после первого кадра,
поэтому к открытию суры обычно уже готов. Шрифты интерфейса — **348 → 184 КБ**:
комплекты Inter «400» и «600» оказались побайтово одинаковым вариативным файлом
(проверено разбором таблиц woff2: fvar/HVAR/STAT), вес задаёт дескриптор
`@font-face`, дубликаты удалены.

**Свайп назад.** Preview монтируется только на подтверждённом горизонтальном
движении, а не на любом касании у левого края; вставляется клоном узла вместо
разбора HTML-строки; положение пишется прямо в композитный слой без участия
React; `will-change` ставится один раз за жест, а не пересоздаётся каждый кадр.

**Лента.** Строка аята вынесена в мемоизированный `AyahRow` — при аудио
перерисовывается одна звучащая строка вместо всех 286. Цикл поиска активного
аята обрывается на первом якоре ниже порога вместо чтения геометрии всех.
Свечение слова измеряется только у звучащего аята. Панель настроек перестала
перерисовываться на каждое событие прокрутки. Слушатель клавиатуры перестал
переподписываться 12 раз в секунду.

**Визуальный язык.** Заведены токены: 11 ступеней кегля по шкале iOS Dynamic
Type, 5 радиусов, 6 отступов, три длительности, две кривые. Во всех экранах
убраны размеры с половинным пикселем и кегли мельче допустимых Apple 11 pt.
Иконки сведены к одной сетке 24×24, одной толщине штриха и трём размерам;
удалены дубликаты (play/pause, шеврон, книга, галочка) и девять неиспользуемых.
Убрано двойное размытие под системной строкой. Зоны касания доведены до 44×44
общим компонентом `components/HitArea.tsx`.

**Проверено:** `npx tsc -b`, `npm test` 220/220, `npm run check:sacred`,
production-сборка, `npx cap sync`. **Не проверено:** ничего не запускалось на
устройстве или в симуляторе — работа шла на Linux-VDS, где нет ни macOS, ни
Xcode, ни браузера. Ощущение плавности подтверждает только владелец на iPhone.

**Сакральный текст не изменялся.** `quran-sources.ts` тронут не был — поменялся
только способ его загрузки.

## Известные ограничения

- **Переход между поаятными MP3 зависит от медиадекодера устройства.** Все пять
  чтецов, включая Люхайдана, начинают выбранный аят быстро из отдельного

- **Живая проверка шла в iOS-симуляторе,** не в браузере. Прогон нашёл три вещи,
  которые сборка не ловит: горизонтальную прокрутку всей страницы, «Мусхаф» в роли

  вычислений в рендере) устранена, а на будущее добавлен глобальный перехват
  ошибок, чтобы вместо пустого экрана было видно сообщение.
- **Android собран и прогнан вживую** (эмулятор Medium_Phone, Android 37 preview).
  Работают: чтение, докачка аудио через CapacitorHttp, воспроизведение,

## Веб-версия

Публичный адрес остаётся **https://l.asrbook.ru**. Сервер `85.198.86.41`
завершает TLS и проксирует приложение на закрытый origin
`62.113.106.30:8091`, webroot `/var/www/an-nur`. Origin открыт firewall и
Caddy ACL только для IP старого edge. Раскладывается из корня проекта:

```
npm run check:sacred
npm run build
rsync -az --delete --exclude '.DS_Store' dist/ root@62.113.106.30:/var/www/an-nur/
```

`https://l.asrbook.ru/audio/luhaidan/*` — постоянный набор коротких MP3 аятов.
Он физически остаётся в `/var/www/quran-ru/audio/luhaidan` на `85.198.86.41` и
обслуживается edge локально до reverse proxy. Поэтому `--delete` нового
webroot не затрагивает 1,35 ГБ аудио и стабильные URL iOS.

Перед переключением созданы конфигурационные резервные копии:
`/etc/caddy/Caddyfile.before-an-nur-origin-20260824-0604` на edge и
`/etc/caddy/Caddyfile.before-an-nur-20260824-0208` на origin. Старая
`/var/www/quran-ru` вне `audio/luhaidan` хранится только как rollback-копия и
не является целью обычного деплоя.

Другие webroot на сервере не являются резервом этого проекта и не должны
использоваться для отката или деплоя без отдельного прямого указания владельца.

В браузере не работает только скачивание аудио в память устройства — оно на
нативных плагинах. Стрим, чтение, поиск, азкары и темы работают. Напоминание
в браузере возможно лишь пока вкладка an-Nur открыта; iOS и Android планируют
его системно и показывают после закрытия приложения.

### 2026-08-11 · Шрифты мусхафа нарезаны по страницам

QCF V4 раздаётся 48 файлами по ~780 КБ, и пара (PUA-код, шрифт) задаёт слово: один и
тот же код в разных файлах — разные слова. Странице нужно ~140 глифов из 2073, поэтому
на открытие уходило в среднем 0.89 МБ, местами 1.78 МБ. Худший случай — служебные
шрифты: страница 77 тянула 924 КБ ради ОДНОГО глифа с названием суры.

`scripts/build-page-fonts.py` режет их по страницам в `public/qcf4/fonts-page/NNN/`
(797 файлов, ~71 КБ на страницу, 3.6% от прежнего). Семейство в CSS получает суффикс
страницы (`QCF4_Hafs_06_p77`) — иначе подмножества столкнулись бы в одном `font-family`
и браузер отдал бы глиф не той страницы, то есть чужое слово внутри аята.

Сакральная сторона: сабсеттинг не рисует глифы, а выбрасывает лишние. Но скрипт всё
равно проверяет каждую страницу дважды и падает при первом расхождении — покрытие
(все коды на месте) и тождество (контур и ширина сверены с оригиналом по хешу пера).
Прогон на всех 604 страницах: расхождений нет.

Исходные 48 шрифтов переехали в `vendor/qcf4-fonts-woff2/` — вне `public`, потому что
в рантайме не нужны, а в пакете были лишними 36 МБ. Они остаются в репозитории: без
них нарезку не повторить.

Чего это стоило по коду: слово теперь знает свою страницу (`hydratePage`), шрифт
просят только аяты вблизи экрана (`useNearViewport`) — иначе смонтированная целиком
сура запрашивала 32 подмножества и файл первого экрана приходил последним; первые
восемь аятов от места чтения просят сразу, минуя наблюдатель (`eager`); лента отдаёт
начало суры, не дожидаясь остальных страниц; датасет альтернативных начертаний (3.9 МБ)
больше не качается, пока читают мусхафом.

Вместо кубиков — `ArabicSkeleton`. `font-display: block` держит текст невидимым около
трёх секунд, а потом показывает запасной шрифт, которого у PUA-кодов не существует, —
отсюда и были ряды квадратов на месте аята.

На сервере (`l.asrbook.ru`) добавлены заголовки кэша по расширению: раньше правила
покрывали только `/assets`, `/fonts`, `/audio`, и шрифты мусхафа уходили вообще без
`Cache-Control` — браузер перекачивал их при каждом открытии суры.
