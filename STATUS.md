# STATUS — QuranRu

## Текущее состояние

Русскоязычное приложение для чтения Корана: арабский текст, перевод Кулиева, аудио с
пословной подсветкой, азкары. Веб + нативные обёртки iOS и Android через Capacitor.

Снято с **QuranIng** (`~/Desktop/QuranIng`, ветка `design/v2`, коммит `7b1c6ad`)
2026-08-09 и упрощено: без ингушского языка, четыре темы вместо двенадцати, два чтеца
вместо восьми, плюс задел под разделы «Намаз» и «Кибла».

Первичное упрощение завершено. Приложение собирается и **проверено на
iOS-симуляторе вживую**: чтение, воспроизведение с караоке-подсветкой,
скачивание сур на устройство и игра с диска — работают.

## Известные ограничения

- **Офлайн-аудио только в нативной обёртке.** В браузере `<audio>` не читает Cache API
  без service worker'а; UI показывает это явно, а не молчит.
- **Оценка размера загрузки — расчётная.** 139 КБ на аят выведено из реальной
  длительности чтения Аляфаси (29.5 ч, замерено по 114 файлам quranicaudio) при
  64 kbps → ~850 МБ на весь Коран. В коде стоит `CHECK:` — уточнить по факту.
- **Живая проверка шла в iOS-симуляторе,** не в браузере. Прогон нашёл три вещи,
  которые сборка не ловит: горизонтальную прокрутку всей страницы, «Мусхаф» в роли
  тёмной темы и полностью нерабочее скачивание (CORS). Один раз WebView ушёл в
  чёрный экран — воспроизвести не удалось; вероятная причина (фризы от тяжёлых
  вычислений в рендере) устранена, а на будущее добавлен глобальный перехват
  ошибок, чтобы вместо пустого экрана было видно сообщение.
- **Android собран и прогнан вживую** (эмулятор Medium_Phone, Android 37 preview).
  Работают: чтение, докачка аудио через CapacitorHttp, воспроизведение,
  фоновое воспроизведение (очередь ушла с 1:1 на 1:6 при свёрнутом приложении),
  аппаратная «назад». Сборка требует JDK 21 — на JDK 25 Gradle 8.14 падает
  с «Unsupported class file major version 69».
  Не проверено: реальный звук в динамике (у эмулятора нет вывода — судим по
  тому, что очередь аятов продолжала идти) и поведение на физическом устройстве.

## История ключевых решений

### 2026-08-12 · Что нашёл аудит после нарезки шрифтов

Нативные обёртки оказались сломаны: в `ios/` и `android/` лежали старые 48
шрифтов, постраничных не было вовсе. В вебе всё работало — расхождение видно
только в нативной сборке. Отсюда правило: правка данных мусхафа заканчивается
не сборкой, а `npx cap sync` и проверкой на симуляторе.

Сбой загрузки шрифта приравнивался к успеху, и текст рисовался без шрифта —
то есть кубиками. Теперь «не смогли» отдельное состояние: скелет плюс плашка с
повтором. Готовность проверяется по статусу `FontFace`, а не через
`document.fonts.check()` — тот без второго аргумента спрашивает про пробел,
которого в подмножестве из одного глифа нет.

Прыжок к аяту искал якорь в одном кадре и молча терялся, если аят ещё не
смонтирован; вдобавок его затирало восстановление позиции. Теперь цель ждёт
появления узла и выигрывает у восстановления.

Тесты выросли со 123 до 146: арифметика семейств и целостность 797 подмножеств.
Последнее — защита от самой дорогой ошибки: правку данных без перегенерации
шрифтов иначе не видно до прода.

### 2026-08-11 · Шрифты мусхафа нарезаны по страницам

QCF V4 раздаётся 48 файлами по ~780 КБ, и пара (PUA-код, шрифт) задаёт слово: один и
тот же код в разных файлах — разные слова. Странице нужно ~140 глифов из 2073, поэтому
на открытие уходило в среднем 0.89 МБ, местами 1.78 МБ. Худший случай — служебные
шрифты: страница 77 тянула 924 КБ ради ОДНОГО глифа с названием суры.

`scripts/build-page-fonts.py` режет их по страницам в `public/qcf4/fonts-page/NNN/`
(797 файлов, ~71 КБ на страницу, 3.6% от прежнего). Семейство в CSS получает суффикс
страницы (`QCF4_Hafs_06_p77`) — иначе подмножества столкнулись бы в одном `font-family`
и браузер отдал бы глиф не той страницы, то есть чужое слово внутри аята.

Сакральная сторона: сабсеттинг не рисует глифы, а выбрасывает лишние. Но скрипт всё
равно проверяет каждую страницу дважды и падает при первом расхождении — покрытие
(все коды на месте) и тождество (контур и ширина сверены с оригиналом по хешу пера).
Прогон на всех 604 страницах: расхождений нет.

Исходные 48 шрифтов переехали в `vendor/qcf4-fonts-woff2/` — вне `public`, потому что
в рантайме не нужны, а в пакете были лишними 36 МБ. Они остаются в репозитории: без
них нарезку не повторить.

Чего это стоило по коду: слово теперь знает свою страницу (`hydratePage`), шрифт
просят только аяты вблизи экрана (`useNearViewport`) — иначе смонтированная целиком
сура запрашивала 32 подмножества и файл первого экрана приходил последним; первые
восемь аятов от места чтения просят сразу, минуя наблюдатель (`eager`); лента отдаёт
начало суры, не дожидаясь остальных страниц; датасет альтернативных начертаний (3.9 МБ)
больше не качается, пока читают мусхафом.

Вместо кубиков — `ArabicSkeleton`. `font-display: block` держит текст невидимым около
трёх секунд, а потом показывает запасной шрифт, которого у PUA-кодов не существует, —
отсюда и были ряды квадратов на месте аята.

На сервере (`l.asrbook.ru`) добавлены заголовки кэша по расширению: раньше правила
покрывали только `/assets`, `/fonts`, `/audio`, и шрифты мусхафа уходили вообще без
`Cache-Control` — браузер перекачивал их при каждом открытии суры.
